# Design

## Context

- `AuthenticationConfig` 以 `InMemoryUserDetailsManager` 建立 `UserDetailsService`，資料來自 `DemoUserProperties`（`app.users[]`）；`DaoAuthenticationProvider` 搭配 `DelegatingPasswordEncoder`（支援 `{bcrypt}`、`{noop}`）。
- `InMemoryUserDetailsManager` 以小寫 key 儲存與查詢帳號，因此現行登入不分大小寫。
- `ApiExceptionHandler` 將所有 `AuthenticationException` 轉為 401 `invalid_credentials`，`DisabledException` 也會走同一路徑。
- `TokenService` 從 `Authentication.getAuthorities()` 去掉 `ROLE_` 前綴並排序後放入 `roles` claim。
- 整合測試（`IntegrationTestSupport` 子類別）共用一個 Spring context，並依賴 `alice` / `admin` 示範帳號。
- 專案目前沒有任何資料庫相依。

需求見 `specs/user-store/spec.md` 與 `specs/token-issuance/spec.md`。

## Goals / Non-Goals

**Goals:**
- 資料表結構明確、由 SQL 腳本管理，可讀；開發時可用 H2 Console 直接檢視與修改。
- `AuthController`、`TokenService`、`SecurityConfig` 不需修改；只替換 `UserDetailsService` 的實作。
- model 與 Mapper 可直接被日後的帳號管理功能重用。

**Non-Goals:**
- 不做資料庫 migration 版本管理（Flyway / Liquibase）。
- 不快取 `UserDetails`；每次登入查一次資料庫。
- 不支援多資料庫方言；SQL 以 H2 2.x 語法撰寫。

## Decisions

### D1：MyBatis + 自訂 `UserDetailsService`
新增 `mybatis-spring-boot-starter`（3.0.3，支援 Boot 3.3）與 `com.h2database:h2`（runtime），測試加 `mybatis-spring-boot-starter-test`。建立 `UserAccount` model、`@Mapper UserMapper` 介面與 `mapper/UserMapper.xml`，以 `DatabaseUserDetailsService implements UserDetailsService` 轉為 Spring Security 的 `User`。

- 替代方案 Spring Data JPA：結構與查詢由 ORM 推導，SQL 不可見；本專案指定採 MyBatis，SQL 明確寫在 XML，與 `schema.sql` 對照容易。

- 替代方案 `JdbcUserDetailsManager`：預設綁定 Spring Security 的 `users` / `authorities` 結構，要支援獨立的 `roles` 與關聯表必須改寫查詢字串，且日後做管理功能時沒有可重用的領域模型。故不採用。

新程式碼放在 `com.example.tokenservice.user` 套件（`UserAccount`、`UserMapper`、`DatabaseUserDetailsService`），`auth` 套件只保留認證流程。

### D2：資料表結構（`schema.sql`）

```sql
CREATE TABLE IF NOT EXISTS users (
    id       BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username VARCHAR(50)  NOT NULL,
    password VARCHAR(255) NOT NULL,
    enabled  BOOLEAN      NOT NULL DEFAULT TRUE,
    CONSTRAINT uk_users_username UNIQUE (username),
    CONSTRAINT ck_users_username_lower CHECK (username = LOWER(username))
);

CREATE TABLE IF NOT EXISTS roles (
    id   BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    CONSTRAINT uk_roles_name UNIQUE (name)
);

CREATE TABLE IF NOT EXISTS user_roles (
    user_id BIGINT NOT NULL,
    role_id BIGINT NOT NULL,
    PRIMARY KEY (user_id, role_id),
    CONSTRAINT fk_user_roles_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE,
    CONSTRAINT fk_user_roles_role FOREIGN KEY (role_id) REFERENCES roles (id) ON DELETE CASCADE
);
```

- `password` 存完整 `DelegatingPasswordEncoder` 格式（`{bcrypt}$2a$...`），長度留 255 以容納 argon2 等其他編碼。
- `roles.name` 存不含前綴的名稱（`USER`、`ADMIN`），轉換時用 `User.builder().roles(...)` 自動加 `ROLE_`，與 `TokenService` 去前綴的邏輯對稱。
- 複合主鍵直接擋下重複指派；`CHECK` 擋下非小寫帳號名稱。
- 表名用 `users`（非 `user`）避開 H2 保留字 `USER`。

### D3：大小寫不敏感登入以「小寫保存 + 查詢前轉小寫」實作
`DatabaseUserDetailsService` 先 `username.toLowerCase(Locale.ROOT)` 再 `findByUsername`。比起 `findByUsernameIgnoreCase` + 無法建立的函式索引，這樣唯一約束與查詢都能直接用 `username` 欄位，且行為與現行 `InMemoryUserDetailsManager` 一致。

### D4：XML Mapper，單一 LEFT JOIN + resultMap 取回帳號與角色
`UserMapper.findByUsername(String username)` 回傳 `UserAccount`（查無時為 `null`），SQL 寫在 `src/main/resources/mapper/UserMapper.xml`：

```xml
<resultMap id="userAccount" type="com.example.tokenservice.user.UserAccount">
    <id property="id" column="id"/>
    <result property="username" column="username"/>
    <result property="password" column="password"/>
    <result property="enabled" column="enabled"/>
    <collection property="roles" ofType="string">
        <result column="role_name"/>
    </collection>
</resultMap>

<select id="findByUsername" resultMap="userAccount">
    SELECT u.id, u.username, u.password, u.enabled, r.name AS role_name
    FROM users u
    LEFT JOIN user_roles ur ON ur.user_id = u.id
    LEFT JOIN roles r ON r.id = ur.role_id
    WHERE u.username = #{username}
</select>
```

- 一條查詢取回帳號與所有角色；`<id>` 讓 MyBatis 把同一使用者的多列合併成一個物件。
- 用 `LEFT JOIN`，沒有角色的使用者也能查到（`roles` 為空 list）。
- `UserAccount` 用可變 POJO（getter/setter）而非 record：MyBatis 的 `<constructor>` 不支援 `<collection>`。
- 設定 `mybatis.mapper-locations: classpath:mapper/*.xml`、`mybatis.configuration.map-underscore-to-camel-case: true`。
- 替代方案「註解 Mapper + `@Many` 第二條查詢」：不需 XML，但每次登入兩條查詢，且多表 SQL 寫在註解中不易閱讀。故不採用。

### D5：結構與資料由 SQL 腳本初始化
- `spring.sql.init.mode: always`（檔案模式的 H2 不被視為 embedded，需明確開啟）。
- 結構以 `schema.sql` 為唯一來源；MyBatis 不產生或檢查結構。
- `data.sql` 必須可重複執行：以 `INSERT INTO ... SELECT ... WHERE NOT EXISTS (...)` 只補缺少的資料，不覆蓋既有資料（檔案模式下改過的密碼不會在重啟時被還原）。關聯以子查詢依名稱取 id，不寫死 id，避免與 identity 序列衝突。

### D6：預設 H2 記憶體模式
```yaml
spring:
  datasource:
    url: jdbc:h2:mem:tokenservice;DB_CLOSE_DELAY=-1
    username: sa
    password: ""
```
要保留資料時改為 `jdbc:h2:file:./data/tokenservice`，並將 `data/` 加入 `.gitignore`。H2 Console 只在 `dev` profile 開啟，見 D9。

### D7：停用帳號
`User.builder().disabled(!enabled)`；`DaoAuthenticationProvider` 的 pre-authentication check 會拋 `DisabledException`，由既有 `ApiExceptionHandler` 回 401 `invalid_credentials`，不需修改 handler。`hideUserNotFoundExceptions` 維持預設 `true`。

### D8：移除 `DemoUserProperties`
刪除 record 與 `application.yml` 的 `app.users`。檢查 `@ConfigurationPropertiesScan` / `@EnableConfigurationProperties` 是否有明確列出它並一併移除。舊設定殘留不會造成啟動錯誤（未綁定的屬性被忽略），這正是 spec「設定檔帳號不生效」所要求的行為。

### D9：H2 Console 只在 `dev` profile、只限本機
- 新增 `application-dev.yml`，設定 `spring.h2.console.enabled: true`（路徑用預設 `/h2-console`）。不設定 `spring.h2.console.settings.web-allow-others`，維持 H2 預設 `false`：非本機的請求由 H2 servlet 自己拒絕。
- 新增 `security.H2ConsoleSecurityConfig`，以 `@ConditionalOnProperty("spring.h2.console.enabled")` 只在 Console 開啟時註冊一條 `@Order(1)` 的 `SecurityFilterChain`：`securityMatcher(PathRequest.toH2Console())`、`permitAll`、停用 CSRF（Console 的表單不帶 CSRF token）、`X-Frame-Options: SAMEORIGIN`（Console 以 frame 組成頁面，預設的 `DENY` 會讓畫面空白）。
- 既有的 `SecurityConfig` 不修改；預設 profile 下沒有這條 chain，`/h2-console` 落入 `anyRequest().authenticated()` 回 401。
- 登入 Console 使用 JDBC 帳密（`jdbc:h2:mem:tokenservice`、`sa`、空密碼），與 JWT 無關。
- 替代方案「要求 ADMIN token」：瀏覽器無法自動帶 Bearer header，實務上無法直接開啟。故不採用。
- 替代方案「寫在 `application.yml` 預設開啟」：正式環境容易忘記關閉。故不採用。
- Console 是獨立的 servlet，不經過 `DispatcherServlet`，MockMvc 打不到；測試要用 `RANDOM_PORT` 的真實 HTTP。

## Risks / Trade-offs

- [記憶體模式資料不保留，執行期的變更重啟即消失] → 文件說明切換檔案模式的方式；本變更不提供管理 API，執行期變更只會來自手動 SQL。
- [多個 Spring test context 共用同名 `mem:tokenservice` 資料庫] → `schema.sql` / `data.sql` 皆為冪等；修改資料的測試使用自己的專屬帳號並在結束時清除，不改動 `alice` / `admin`。
- [MyBatis 不會在啟動時檢查 SQL 與資料表是否一致，欄位打錯要到執行查詢才會發現] → `UserMapperTest` 與整合測試涵蓋 `findByUsername` 的每個欄位對應。
- [H2 Console 可直接讀寫帳號、密碼雜湊與停用狀態] → 只在 `dev` profile 開啟、只接受本機連線；README 標明正式環境不可啟用 `dev`。
- [每次登入都查資料庫] → H2 記憶體模式延遲可忽略；之後若改外部資料庫再評估 `UserCache`。
- [`data.sql` 內含示範帳號的 bcrypt 雜湊] → 與現行 `application.yml` 相同的風險等級；README 標註僅供展示。
- [SQL 為 H2 方言] → 換資料庫時需重寫腳本，屆時應導入 migration 工具（Non-Goal）。

## Migration Plan

1. 部署新版本：啟動時自動建表並植入 `alice` / `admin`，密碼與角色與舊設定相同，用戶端無感。
2. 若有人在自己的設定檔加了 `app.users` 帳號，需改以 SQL 寫入資料庫（README 提供範例 INSERT）。
3. 回滾：還原至前一版即可，無持久化資料需處理（預設記憶體模式）。
